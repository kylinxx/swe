# Coding Agent Mini Benchmark

这个小 benchmark 用来评估 coding agent 在真实编程任务中的表现。它不是看“会不会聊天”，而是看它能不能在限定工作区里：

- 读懂任务
- 找到 bug
- 修改代码
- 跑测试验证
- 在失败后继续修正

## 评估维度

1. **任务成功率**：测试是否最终通过。
2. **工具使用质量**：是否先读再改、先搜再修。
3. **鲁棒性**：遇到错误时是否能继续分析，而不是直接崩掉。
4. **效率**：完成任务用了多少轮模型调用和工具调用。
5. **可复盘性**：最终是否能说明自己做了什么。

## 推荐评分

- **5 分**：一次完成，修改干净，测试通过。
- **4 分**：完成任务，过程有少量绕路。
- **3 分**：最终完成，但需要较多轮次。
- **2 分**：部分完成，仍需人工介入。
- **1 分**：失败，但能返回清晰错误。
- **0 分**：直接崩溃或越界。

## 使用方式

对每个任务：

1. 进入对应目录。
2. 先运行测试，确认初始失败。
3. 让 agent 修复。
4. 再运行测试，确认通过。
5. 记录轮数、耗时和最终结果。

## 自动跑脚本

仓库根目录下的 `scripts/run_mini_benchmark.py` 可以自动：

- 复制每个任务到临时目录
- 先跑一次初始测试
- 调用 `coding_agent` 修复任务
- 再跑一次测试并统计结果

用法示例：

```bash
python scripts/run_mini_benchmark.py
```

如果你还没设置 `OPENAI_API_KEY`，脚本会先提示你补环境变量，再正式跑评估。

这些任务是故意带 bug 的，不要把它们加进默认测试发现路径里。
